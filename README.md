# PromptPortal — образовательный портал по промпт-инжинирингу

Портал, в котором теория и практика переплетены: читаешь абзац — сразу проверяешь
понимание интерактивным упражнением прямо в тексте. Один и тот же компонент
работает и как inline-вставка в статью, и как часть итогового теста со счётом.

---

## 1. Технологии и почему именно они

### Клиент (`frontend/`)
- **Angular 17+ (standalone components)** — выбрано из-за строгой типизации,
  встроенного DI и удобной модульности: одно и то же упражнение легко
  переиспользовать в разных контекстах.
- **Angular Signals** — реактивное состояние внутри компонентов упражнений и
  тест-сессии без внешних стейт-менеджеров (Redux/NgRx избыточны для объёма
  проекта).
- **Angular Router с lazy-loading** — каждая страница подгружается отдельным
  чанком.
- **HttpClient + функциональный интерцептор** — единая точка подстановки JWT.
- **SCSS** — без тяжёлых UI-библиотек, чтобы компоненты были лёгкими
  и переносимыми.

### Сервер (`server/`)
- **Node.js + Express** — минимальный API: авторизация, раздача контента,
  сохранение прогресса.
- **JWT + bcryptjs** — простая и понятная аутентификация для учебного проекта.
- **JSON-файлы как хранилище** — быстрый старт без развёртывания БД.
  Архитектурно изолированы в **репозиториях** (см. ниже), поэтому замена
  хранилища на PostgreSQL / SQLite / MongoDB не затронет ни один роут.

### Почему такая архитектура сервера
Весь доступ к данным идёт через классы-репозитории
(`UserRepo`, `ArticleRepo`, `TestRepo`, `ProgressRepo`, `AttemptRepo`).
Каждый репозиторий инкапсулирует методы (`findByEmail`, `create`,
`findBySlug`, …) и не знает, что под ним — JSON-файл. Замена хранилища =
написать новые репозитории с тем же интерфейсом и переключить фабрику
`server/src/db/index.js`. Роуты при этом не меняются.

## 2. Компоненты: что создано и как устроено

### 2.1 Базовый класс упражнений — `BaseExerciseComponent`

Абстрактный класс, от которого наследуются все типы упражнений. Даёт каждому
компоненту единый контракт:

- `@Input() config: ExerciseConfig` — вопрос, варианты, правильный ответ,
  объяснение, вес балла;
- `@Input() mode: 'inline' | 'test'` — режим работы;
- `@Output() answered: EventEmitter<ExerciseResult>` — результат ответа;
- `checked`, `score` — сигналы состояния;
- `emitResult(score, partial)` — универсальный метод фиксации ответа;
- `resetState()` — сброс для кнопки «Попробовать снова» (только inline).

Благодаря этому **любой новый тип упражнения** подключается за ~30 строк:
наследуешься от базового класса, рисуешь UI, вызываешь `emitResult` — и он
автоматически работает и в статье, и в тесте.

### 2.2 Обёртка — `ExerciseHostComponent`

Принимает `config` и по полю `type` через `ngSwitch` рендерит нужный
компонент. Именно сюда «приходят» все блоки типа `exercise` из статьи и
вопросы из теста. Добавление нового типа = одна строка в шаблоне и один
`case` в `ngSwitch`.

### 2.3 Типы упражнений (6 штук)

| Тип | Файл | Что проверяет |
|---|---|---|
| `multiple-choice` | `exercises/multiple-choice` | Один/несколько правильных ответов |
| `match-pairs` | `exercises/match-pairs` | Соответствие «термин ↔ определение» с частичным баллом |
| `fill-the-blank` | `exercises/fill-the-blank` | Вставка пропущенного слова (нормализация регистра и пробелов) |
| `true-false` | `exercises/true-false` | Верно / неверно с обязательным объяснением |
| `order-steps` | `exercises/order-steps` | Правильный порядок шагов, частичный балл по позициям |
| `prompt-builder` **(кастомный)** | `exercises/prompt-builder` | Собрать промпт из блоков: назначить фрагменту роль / контекст / задачу / формат |

**Кастомный компонент — `PromptBuilder`.** Это уникальный тип для темы
промпт-инжиниринга: пользователю даны фрагменты промпта («Ты — технический
писатель», «Аудитория — junior-разработчики», …) и четыре слота (роль,
контекст, задача, формат). Он должен распределить фрагменты по слотам через
`<select>`. Оценка — по доле верных назначений, с частичным баллом.

### 2.4 Продвинутые компоненты (реализованы как конфигурации того же движка)

- **CaseStudy** — реализуется как `FillTheBlank` с развёрнутым объяснением
  или как `PromptBuilder` с расширенным набором слотов.
- **SpotTheHallucination** — как `MultipleChoice` с `multiple: true`, где
  правильные опции — «подозрительные» фрагменты ответа.
- **PromptSimulator** — как `TrueFalse` / `MultipleChoice` с заготовленной
  парой «промпт → ответ AI» в поле `statement` / `question`.

Такой подход экономит код: не плодим типы, а используем богатые
конфигурации одного движка.

### 2.5 Оценка и обратная связь

- Каждое упражнение возвращает `ExerciseResult`:
  `{ exerciseId, score, maxScore, isCorrect, partial }`.
- Частичная правильность (`MatchPairs`, `OrderSteps`, `PromptBuilder`)
  считается как `(верных / всего) * maxScore`.
- `FeedbackPanelComponent` показывает три состояния: ✓ верно / ◐ частично
  верно / ✗ неверно и всегда выводит `explanation` — «почему так».

### 2.6 Два режима работы

- **`inline`** — компонент встроен в статью. Нет общего счёта, результат
  остаётся локальным, доступна кнопка «Попробовать снова».
- **`test`** — компонент внутри `TestComponent`. Каждый ответ летит в
  `TestSessionService`, который накапливает результаты, считает прогресс
  и итоговый балл.

Переключение — через `@Input() mode`. Никаких ветвлений в логике самого
упражнения: просто проверяем `mode === 'inline'` там, где нужно показать
кнопку retry.

### 2.7 Тест-сессия

`TestSessionService` — единственное место, где живёт состояние прохождения
теста. Через сигналы отдаёт `current()`, `index()`, `total()`, `score()`,
`maxScore()`, `finished()`. Компоненты-упражнения о нём ничего не знают —
они просто эмитят результат наверх.


## 4. Локальный запуск

### 4.1 Требования
- Node.js ≥ 18
- npm ≥ 9
- Angular CLI ≥ 17 (`npm i -g @angular/cli`)

### 4.2 Сервер

```bash
cd server
npm install
cp .env.example .env
npm run dev
```

#### API доступен на http://localhost:3000
.env (можно оставить значения по умолчанию):

```text
PORT=3000
JWT_SECRET=change-me
DB_BACKEND=json
DATA_DIR=./src/data
```
### 4.3 Клиент

```bash
cd frontend
npm install
ng serve
```

#### UI доступен на http://localhost:4200
Клиент ожидает API на http://localhost:3000/api — это прописано в
frontend/src/environments/environment.ts.


### 5. Как попробовать: сценарий из 5 минут
Открыть http://localhost:4200. Видим лендинг с кнопками
«Начать бесплатно» и «Все курсы».

Зарегистрироваться: /auth/register → email + пароль →
автоматический редирект на список курсов.

Открыть курс: Курсы → Основы промпт-инжиниринга →
карточка курса со списком статей.

Пройти статью «Как работают LLM (на уровне интуиции)»:

читаем вводный абзац;

натыкаемся на True/False — нажимаем «Неверно», «Проверить» →
появляется зелёный фидбэк и объяснение;

ниже — MultipleChoice: выбираем вариант, «Проверить».

внизу статьи — кнопка «Отметить как прочитанное» (сохраняет
прогресс на сервере) и «Перейти к тесту →».

Открыть статью «Структура эффективного промпта» — там нас ждут
уже 4 упражнения: MatchPairs, FillTheBlank, OrderSteps и
кастомный PromptBuilder:

в MatchPairs кликаем слева по термину, справа по определению — пары
соединяются. Проверяем — видим частичный балл, если ошиблись в одной из
четырёх пар;

в OrderSteps двигаем шаги стрелками ↑/↓;

в PromptBuilder через выпадающие списки назначаем каждому фрагменту
свой блок промпта и проверяем.

Пройти итоговый тест: кнопка «Пройти итоговый тест» →
/tests/prompt-basics-test:

сверху — прогресс-бар N / M и счётчик «вопрос X из Y»;

отвечаем, «Проверить» → ответ фиксируется в сессии → «Далее →»;

после последнего вопроса — экран «Тест завершён» с суммой баллов и
кнопкой «Сохранить результат» → редирект на экран результата
со разбивкой по каждому упражнению.

Открыть профиль (/profile) — видим список пройденных статей с
датами и таблицу попыток тестов с баллами.

Как проверить оба режима одного компонента
Откройте frontend/src/app/features/article/article.component.ts и
frontend/src/app/features/test/test.component.ts. В обоих используется
<app-exercise-host [config]="..." [mode]="..."> — единственная разница
в mode ('inline' vs 'test'). Это и есть демонстрация переиспользуемости.

Как проверить частичный балл
В тесте match-pairs (вопрос «Соотнесите блок промпта с примером»)
соедините 3 из 4 пар верно → нажмите «Проверить» → увидите жёлтое состояние
«◐ Частично верно — 1.5 / 2».

### 6. Развитие проекта
Добавить новый тип упражнения
Создать frontend/src/app/exercises/my-type/my-type.component.ts,
унаследоваться от BaseExerciseComponent.

В методе проверки вызвать this.emitResult(score, partial).

Добавить case в ExerciseHostComponent и новое значение в
ExerciseType (core/models).

Добавить вопрос в тест
Отредактировать server/src/data/tests.json.

Добавить статью
Отредактировать server/src/data/articles.json.

Заменить хранилище на PostgreSQL / SQLite / MongoDB
Написать новые классы UserRepo, ArticleRepo, … с теми же методами.
Переключить фабрику в server/src/db/index.js. Роуты не меняются.

### 7. Деплой
Не обязателен для сдачи. Рекомендуемая схема:

Сервер: Render / Railway (Node-сервис, npm start).

Клиент: Vercel / Netlify / Cloudflare Pages — ng build,
публикуется содержимое dist/frontend/browser/.

В environment.production.ts указать публичный URL API.

        
### p.s. для разработчиков
**Стандартизация коммитов:** Conventional Commits + `@commitlint/cli` + `husky`. Настроены скоупы: `frontend`, `server`, `shared`, `ci`.
При неверном коммите будет ругаться. 
Структура коммита `<type>(<scope>): <desc>`
- type: feat, fix, chore, docs, refactor, test, perf
- scope: frontend, server, shared, ci, deps (опционально, но рекомендуется)
- Пример: feat(server): add JWT refresh endpoint

**Если коммиты проходят без проверки**:
- Убедитесь, что установка выполнялась через npm install (триггерит prepare).
- Проверьте наличие папки .husky/ и файлов внутри неё
- На Windows используйте Git Bash или убедитесь, что файлы хуков сохранены с LF окончаниями
